# Talon ATS API Design

## 1. Protocol and representation

- Base path: `/api/v1`.
- JSON request/response bodies and `application/problem+json` failures.
- OAuth 2.0 bearer access tokens issued by Cognito.
- UUID resource identifiers.
- ISO 8601 UTC timestamps; IANA time zones in scheduling DTOs.
- Cursor pagination using opaque, signed/encoded cursors.
- OpenAPI is generated by Spring and the TypeScript client is regenerated in CI.

Required headers:

- `Authorization: Bearer <token>`
- `X-Correlation-Id` accepted/generated on every request.
- `Idempotency-Key` on retriable creation/side-effect commands.
- `If-Match: "<version>"` on optimistic mutable commands.

## 2. Authentication and workspace bootstrap

| Method | Path | Role | Behavior |
|---|---|---|---|
| GET | `/session` | Authenticated | Resolve user, memberships, active workspace, role, and permissions |
| POST | `/workspaces` | Authenticated without membership | Create first workspace and admin membership |
| GET | `/members` | Admin | List workspace members |
| PATCH | `/members/{membershipId}` | Admin | Change fixed role/status with last-admin protection |
| POST | `/invitations` | Admin | Create expiring single-use invitation |
| POST | `/invitations/{token}/accept` | Authenticated invited user | Accept matching-email invitation |

The server derives workspace from membership/context; clients cannot assert arbitrary tenant IDs in request bodies.

## 3. Job APIs

| Method | Path | Role | Behavior |
|---|---|---|---|
| GET | `/jobs` | Staff subject to visibility | Department/status/filter cursor list |
| POST | `/jobs` | Recruiter/Admin | Create draft and copy default pipeline |
| GET | `/jobs/{jobId}` | Assigned staff/Admin | Job detail, stages, counts, team |
| PATCH | `/jobs/{jobId}` | Recruiter/Admin | Edit draft/safe mutable fields using version |
| PUT | `/jobs/{jobId}/pipeline` | Recruiter/Admin | Replace ordered draft stage configuration |
| PUT | `/jobs/{jobId}/hiring-team` | Recruiter/Admin | Replace validated team assignments |
| PUT | `/jobs/{jobId}/scorecard-template` | Recruiter/Admin | Create next rubric version |
| POST | `/jobs/{jobId}/publish` | Recruiter/Admin | Validate and activate job |
| POST | `/jobs/{jobId}/hold` | Recruiter/Admin | Place active job on hold |
| POST | `/jobs/{jobId}/close` | Recruiter/Admin | Close job with reason |

`POST /jobs` accepts role basics only. Wizard steps save the same draft incrementally, so browser refresh does not lose validated work.

## 4. Candidate and application APIs

| Method | Path | Role | Behavior |
|---|---|---|---|
| GET | `/candidates` | Recruiter/Admin; scoped HM | Cursor list and filters |
| POST | `/candidates` | Recruiter/Admin | Create or return duplicate-conflict information |
| GET | `/candidates/{candidateId}` | Authorized staff | Candidate identity and authorized application summaries |
| PATCH | `/candidates/{candidateId}` | Recruiter/Admin | Update contact/profile data |
| POST | `/jobs/{jobId}/applications` | Recruiter/Admin | Link candidate to job at initial stage |
| GET | `/applications/{applicationId}` | Authorized team | Application detail and current version |
| POST | `/applications/{applicationId}/transitions` | Recruiter/HM/Admin | Advance/move/terminal command |
| GET | `/applications/{applicationId}/activity` | Authorized team | Cursor timeline |
| POST | `/candidates/{candidateId}/notes` | Authorized team | Add note and mentions |

Example transition request:

```json
{
  "command": "MOVE_TO_STAGE",
  "targetStageId": "7b5894cb-8b20-4d6c-87e8-bfca685ca331",
  "reasonCode": null,
  "reasonText": null,
  "expectedVersion": 7
}
```

Terminal commands require an allowed reason code and optional bounded detail. A version mismatch returns `409 APPLICATION_VERSION_CONFLICT` with the latest resource version.

## 5. Files and imports

| Method | Path | Behavior |
|---|---|---|
| POST | `/files/uploads` | Authorize category/ownership and return presigned upload |
| POST | `/files/{fileId}/complete` | Verify object metadata and enqueue scan |
| GET | `/files/{fileId}/download` | Return short-lived authorized download |
| POST | `/imports` | Create import for one job and expected CSV/ZIP metadata |
| POST | `/imports/{importId}/validate` | Enqueue validation after uploads complete |
| GET | `/imports/{importId}` | Status and counters |
| GET | `/imports/{importId}/rows` | Cursor validation preview |
| POST | `/imports/{importId}/confirm` | Idempotently begin creation of valid rows |
| POST | `/imports/{importId}/cancel` | Cancel before processing boundary |
| GET | `/imports/{importId}/errors.csv` | Authorized generated error report |

Presigned requests bind object key, content length/type where supported, checksum, and short expiry. Completing an upload does not make a file usable before scan success.

## 7. Interview, scorecard, and scheduling APIs

| Method | Path | Behavior |
|---|---|---|
| POST | `/interviews` | Create draft interview with rubric snapshot/panel |
| GET | `/applications/{id}/interviews` | Authorized interview list |
| GET | `/interviews/{id}/scorecard` | View/edit own scorecard and visibility summary |
| PUT | `/interviews/{id}/scorecard` | Save draft responses |
| POST | `/interviews/{id}/scorecard/submit` | Validate and lock |
| POST | `/scorecards/{id}/reopen` | Admin/recruiter audited reopen |
| POST | `/calendar-connections/google/start` | Begin OAuth with state/PKCE |
| GET | `/calendar-connections/google/callback` | Validate callback and store secret reference |
| POST | `/scheduling/availability` | Resolve panel free/busy for a bounded interval |
| POST | `/schedule-holds` | Create expiring candidate/panel slot hold |

## 8. Offer and communication APIs

| Method | Path | Behavior |
|---|---|---|
| POST | `/offers` | Create draft for an application |
| PATCH | `/offers/{id}` | Create/update active draft version |
| POST | `/offers/{id}/documents` | Attach scanned/generated document to active version |
| POST | `/offers/{id}/submit` | Freeze version and activate approval chain |
| POST | `/offers/{id}/approvals/{stepId}/approve` | Approve current ordered step |
| POST | `/offers/{id}/approvals/{stepId}/reject` | Reject current ordered step with comment |

Compensation endpoints require compensation visibility in addition to general application access.

## 9. Search, notifications, and reports

| Method | Path | Behavior |
|---|---|---|
| GET | `/search?q=&types=&cursor=` | Authorized candidate/job matches and navigation actions |
| GET | `/notifications` | Recipient cursor list |
| POST | `/notifications/{id}/read` | Idempotent mark read |
| POST | `/notifications/read-all` | Mark visible notifications read |
| GET | `/reports/overview` | KPI cards and comparison period |
| GET | `/reports/funnel` | Furthest-stage counts/conversion |
| GET | `/reports/hires-by-source` | Accepted hire source totals |
| GET | `/reports/interview-volume` | Weekly scheduled non-cancelled totals |

Report filters use `from`, `to`, `departmentId`, `jobId`, and timezone. Date ranges are bounded to protect operational queries.

## 10. Bulk command API

`POST /api/v1/applications/bulk-commands` accepts at most 2,000 explicit application IDs, command type, reason/parameters, and an idempotency key. The server authorizes every item. For large commands it returns `202 Accepted` with an operation ID and exposes item-level success/failure; it never silently skips unauthorized records.

## 11. Error codes

Stable codes include:

- `VALIDATION_FAILED`
- `AUTHENTICATION_REQUIRED`
- `WORKSPACE_MEMBERSHIP_REQUIRED`
- `ACTION_FORBIDDEN`
- `RESOURCE_NOT_FOUND`
- `APPLICATION_VERSION_CONFLICT`
- `JOB_PIPELINE_LOCKED`
- `ILLEGAL_STATE_TRANSITION`
- `IDEMPOTENCY_KEY_REUSED`
- `IMPORT_VALIDATION_FAILED`
- `UNSAFE_FILE`
- `AI_PROVIDER_UNAVAILABLE`
- `CALENDAR_CONFLICT`
- `CALENDAR_CONNECTION_REQUIRED`
- `OFFER_APPROVAL_OUT_OF_ORDER`
- `OFFER_VERSION_CHANGED`
- `RATE_LIMITED`

Validation failures provide field paths. Provider failures do not expose provider credentials or raw unsafe payloads.

## 12. Compatibility policy

- Additive response fields are non-breaking.
- Removing/renaming fields or changing semantics requires a new API version or controlled migration.
- Event schemas have independent integer versions.
- Frontend and backend from one release are deployed together, but the backend tolerates the immediately previous frontend during rolling deployment.
- OpenAPI diff checks block unapproved breaking changes.
