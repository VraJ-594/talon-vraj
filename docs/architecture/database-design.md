# Talon ATS Database Design

## 1. Database principles

- Supabase-hosted PostgreSQL is the authoritative transactional database; local Docker and Testcontainers use compatible PostgreSQL.
- All tenant-owned tables contain a non-null `workspace_id` UUID.
- Primary keys are UUIDs generated by the application or PostgreSQL.
- Timestamps use `timestamptz` and UTC.
- Money uses `amount_minor bigint` plus ISO `currency char(3)`.
- Mutable aggregates include `version bigint` for optimistic locking.
- Business deletion is soft only when recovery is required; privacy purge removes or irreversibly anonymizes PII.
- Historical transitions, activity, approval versions, and security audit records are append-only.
- Foreign keys, checks, unique constraints, and partial indexes protect invariants independently of application code.

The application connects with standard JDBC through the TLS Supavisor session pooler in session mode. Flyway owns schema changes. Supabase-specific Auth, Storage, Edge Functions, and Data APIs are outside the application boundary, preserving PostgreSQL portability. The Free plan is allowed for development/demo only; production requires a non-pausing paid tier with automated backups/PITR and a tested restore procedure.

## 2. Tenant and identity tables

### `workspace`

`id`, `name`, `slug`, `default_timezone`, `retention_months`, `created_at`, `created_by`, `version`.

Unique: normalized `slug`. Default retention is 24 months.

### `app_user`

`id`, `cognito_subject`, `email`, `display_name`, `status`, `created_at`, `last_login_at`.

The user identity is global only for authentication. It grants no record access without membership.

### `workspace_membership`

`id`, `workspace_id`, `user_id`, `role`, `status`, `joined_at`, `version`.

Unique: `(workspace_id, user_id)`. Roles are `WORKSPACE_ADMIN`, `RECRUITER`, `HIRING_MANAGER`, `INTERVIEWER`.

### `workspace_invitation`

`id`, `workspace_id`, `email`, `role`, `token_hash`, `expires_at`, `accepted_at`, `invited_by`, `created_at`.

Only hashes are stored. Active duplicates use a partial unique index.

## 3. Job configuration tables

### `department`

`id`, `workspace_id`, `name`, `normalized_name`, `active`, `created_at`, `version`.

Unique: `(workspace_id, normalized_name)`.

### `job`

`id`, `workspace_id`, `department_id`, `title`, `code`, `description`, `requirements`, `location_mode`, `location_label`, `timezone`, `band_min_minor`, `band_max_minor`, `currency`, `owner_membership_id`, `status`, `published_at`, `closed_at`, `created_at`, `updated_at`, `version`.

Unique: `(workspace_id, code)`. Checks enforce band minimum not greater than maximum and publication fields appropriate to status.

### `pipeline_template` and `pipeline_template_stage`

Templates belong to a workspace. Stages contain stable `stage_type`, display name, position, color, and active flag. Terminal outcomes are not ordinary editable template stages.

### `job_stage`

`id`, `workspace_id`, `job_id`, `name`, `stage_type`, `position`, `color`, `created_at`, `version`.

Unique: `(job_id, position)` and `(job_id, lower(name))`. Structural edits are blocked by the service after publication/application creation.

### `job_hiring_team_member`

`job_id`, `workspace_id`, `membership_id`, `assignment_role`, `created_at`.

Unique: `(job_id, membership_id, assignment_role)`.

### `scorecard_template`, `scorecard_template_section`, `scorecard_template_criterion`

Templates are versioned per job. Criteria define prompt, description, scale minimum/maximum, weight, and position. Publishing a new version does not mutate interview snapshots.

## 4. Candidate and application tables

### `candidate`

`id`, `workspace_id`, `first_name`, `last_name`, `email`, `normalized_email`, `phone`, `location`, `current_company`, `current_title`, `linkedin_url`, `github_url`, `created_at`, `updated_at`, `purged_at`, `version`.

Unique active identity: `(workspace_id, normalized_email)` where `purged_at is null`. Cross-workspace matching is forbidden.

### `application`

`id`, `workspace_id`, `candidate_id`, `job_id`, `current_stage_id`, `assigned_recruiter_id`, `source_type`, `source_detail`, `status`, `outcome`, `applied_at`, `terminal_at`, `latest_assessment_id`, `created_at`, `updated_at`, `version`.

Unique: `(workspace_id, candidate_id, job_id)`. `status` is `ACTIVE|TERMINAL`; outcome is null until terminal.

### `stage_transition`

`id`, `workspace_id`, `application_id`, `from_stage_id`, `to_stage_id`, `from_outcome`, `to_outcome`, `reason_code`, `reason_text`, `actor_membership_id`, `source`, `occurred_at`, `correlation_id`.

Append-only. Index `(workspace_id, application_id, occurred_at)` and report-oriented indexes by job/stage/time.

### `activity_event`

`id`, `workspace_id`, `candidate_id`, `application_id`, `event_type`, `actor_membership_id`, `summary`, `metadata jsonb`, `occurred_at`, `correlation_id`.

Metadata contains display-safe structured details and references, not credentials or full resume/email bodies.

### `candidate_note`

`id`, `workspace_id`, `candidate_id`, `application_id`, `body`, `author_membership_id`, `created_at`, `edited_at`, `version`.

Mentions reference memberships through `note_mention` rather than parsing names during notification delivery.

## 5. File and import tables

### `file_object`

`id`, `workspace_id`, `candidate_id`, `application_id`, `category`, `original_name`, `storage_key`, `content_type`, `size_bytes`, `sha256`, `scan_status`, `created_by`, `created_at`, `deleted_at`, `version`.

Unique storage key. Download requires database authorization before generating a presigned URL.

### `import_job`

`id`, `workspace_id`, `job_id`, `csv_file_id`, `zip_file_id`, `status`, `total_rows`, `valid_rows`, `invalid_rows`, `duplicate_rows`, `processed_rows`, `created_by`, `created_at`, `confirmed_at`, `completed_at`, `version`.

Statuses: `UPLOADING`, `VALIDATING`, `PREVIEW_READY`, `CONFIRMED`, `PROCESSING`, `COMPLETED`, `COMPLETED_WITH_ERRORS`, `FAILED`, `CANCELLED`.

### `import_row`

`id`, `workspace_id`, `import_job_id`, `row_number`, `normalized_payload jsonb`, `validation_errors jsonb`, `duplicate_candidate_id`, `candidate_id`, `application_id`, `processing_status`, `processed_at`.

Unique: `(import_job_id, row_number)`.

## 6. AI assessment tables

### `job_scoring_rubric`

`id`, `workspace_id`, `job_id`, `version_number`, `criteria jsonb`, `admin_prompt_override`, `created_by`, `created_at`, `active`.

The normal UI writes structured criteria. Raw prompt override is admin-only and retained for audit/reproducibility.

### `ai_assessment`

`id`, `workspace_id`, `application_id`, `resume_file_id`, `rubric_id`, `provider`, `model`, `prompt_version`, `status`, `overall_score`, `confidence`, `criteria_result jsonb`, `matched_skills jsonb`, `missing_skills jsonb`, `evidence jsonb`, `warnings jsonb`, `provider_request_id`, `started_at`, `completed_at`, `error_code`, `created_at`.

Index review ordering by `(workspace_id, status, overall_score desc, created_at)`. Failed assessments remain visible and retryable; they do not imply rejection.

## 7. Interview and scheduling tables

### `interview`

`id`, `workspace_id`, `application_id`, `title`, `interview_type`, `status`, `starts_at`, `ends_at`, `timezone`, `location_or_link`, `external_event_id`, `calendar_provider`, `rubric_snapshot jsonb`, `created_by`, `created_at`, `updated_at`, `version`.

### `interview_panelist`

`interview_id`, `workspace_id`, `membership_id`, `round_name`, `duration_minutes`, `status`, `external_event_id`.

Unique: `(interview_id, membership_id, round_name)`.

### `scorecard`

`id`, `workspace_id`, `interview_id`, `panelist_membership_id`, `status`, `responses jsonb`, `recommendation`, `overall_rating`, `submitted_at`, `reopened_at`, `reopened_by`, `version`.

Unique: `(interview_id, panelist_membership_id)`. Responses validate against the rubric snapshot in application code.

### `calendar_connection`

`id`, `workspace_id`, `membership_id`, `provider`, `provider_account_id`, `encrypted_token_secret_arn`, `scopes`, `sync_cursor`, `webhook_channel_id`, `webhook_expires_at`, `status`, `connected_at`, `last_synced_at`, `version`.

Token ciphertext or secret values never appear in ordinary database columns.

### `schedule_hold`

`id`, `workspace_id`, `application_id`, `starts_at`, `ends_at`, `timezone`, `panelist_ids jsonb`, `expires_at`, `created_by`, `status`, `version`.

Expired holds are ignored by availability queries and cleaned asynchronously.

## 8. Offer and communication tables

### `offer`

`id`, `workspace_id`, `application_id`, `status`, `active_version_id`, `accepted_at`, `declined_at`, `created_by`, `created_at`, `updated_at`, `version`.

One non-terminal active offer per application is enforced with a partial unique index.

### `offer_version`

`id`, `workspace_id`, `offer_id`, `version_number`, `level`, `base_amount_minor`, `currency`, `equity_description`, `sign_on_amount_minor`, `start_date`, `expires_on`, `document_file_id`, `created_by`, `created_at`, `submitted_at`, `approved_at`.

Unique: `(offer_id, version_number)`.

### `offer_approval_step`

`id`, `workspace_id`, `offer_version_id`, `position`, `approver_membership_id`, `label`, `status`, `decision_comment`, `decided_at`, `created_at`.

Unique: `(offer_version_id, position)`. Only the lowest-position pending step with all predecessors approved is actionable.

### `message`

`id`, `workspace_id`, `candidate_id`, `application_id`, `message_type`, `subject`, `body_html`, `body_text`, `to_address`, `from_address`, `status`, `provider_message_id`, `idempotency_key`, `created_by`, `created_at`, `sent_at`, `version`.

Unique: `(workspace_id, idempotency_key)` where not null.

### `message_delivery_event`

`id`, `workspace_id`, `message_id`, `provider_event_id`, `event_type`, `occurred_at`, `payload_reference`, `created_at`.

Unique: provider event ID. Raw provider payloads are retained only according to security policy.

## 9. Platform tables

### `notification`

`id`, `workspace_id`, `recipient_membership_id`, `type`, `title`, `body`, `target_type`, `target_id`, `deduplication_key`, `read_at`, `created_at`.

Unique: `(recipient_membership_id, deduplication_key)` where a key is supplied.

### `outbox_event`

`id`, `workspace_id`, `event_type`, `schema_version`, `aggregate_type`, `aggregate_id`, `payload jsonb`, `correlation_id`, `occurred_at`, `published_at`, `attempt_count`, `last_error`.

Index unpublished records by `(published_at, occurred_at)`.

### `processed_message`

`consumer_name`, `event_id`, `processed_at`, `result_reference`.

Primary key: `(consumer_name, event_id)`.

### `audit_event`

`id`, `workspace_id`, `actor_user_id`, `actor_membership_id`, `action`, `resource_type`, `resource_id`, `outcome`, `reason`, `ip_hash`, `user_agent_hash`, `metadata jsonb`, `occurred_at`, `correlation_id`.

Append-only and excluded from ordinary application deletion.

## 10. Search indexes

- Candidate `tsvector` over names, company, title, and normalized email.
- Job `tsvector` over title, code, department, description, and requirements.
- Trigram indexes for candidate name/email and job title/code typo tolerance.
- Every search index/query begins with workspace scope and applies role/resource visibility.

## 11. RLS policy pattern

```sql
alter table candidate enable row level security;
alter table candidate force row level security;

create policy candidate_workspace_isolation on candidate
using (workspace_id = current_setting('app.workspace_id', true)::uuid)
with check (workspace_id = current_setting('app.workspace_id', true)::uuid);
```

Migration and maintenance roles do not serve application traffic. Integration tests prove that missing or incorrect tenant context returns no rows and cannot insert data.

## 12. Retention and purge

- Rejected and withdrawn applications become eligible after the workspace retention period, default 24 months.
- Hired candidates are not automatically purged while employment/legal retention requirements remain unresolved; administrators receive explicit policy controls.
- Purge removes contact fields, notes, message bodies, resume/offer objects, provider identifiers, and AI evidence containing PII.
- Stage/source/date facts may be converted to non-identifying aggregate rows.
- Security audit evidence remains according to the audit policy and contains hashed/minimized network identifiers.

## 13. Migration rules

- Flyway migrations are immutable after merging.
- Destructive changes use expand/migrate/contract releases.
- New non-null columns receive a safe default/backfill before constraint enforcement.
- Large backfills run as resumable jobs rather than blocking deployment migrations.
- Every migration is tested from an empty database and from the previous release schema.
